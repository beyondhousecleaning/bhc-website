```jsx
// The static-params triple. Parent segments get NO generateStaticParams at all — the LEAF
// returns every dynamic segment in the path. [CITED: nextjs.org generate-static-params]
export const dynamicParams = false;

export function generateStaticParams() {
  const out = [];
  for (const town of PUBLISHED_TOWNS) {        // never the raw TOWNS array
    for (const service of town.services) {     // the town's OWN six
      out.push({ region: town.urlRegion, town: town.slug, service });
    }
  }
  return out;                                  // 126 objects at batch 1
}

export async function generateMetadata({ params }) {
  const { region, town, service } = await params;   // `await` is MANDATORY in Next 16
  // …
}
```

`await params` in **both** exports. Next 16 removed synchronous access outright: a sync read is a
build error, and an un-awaited `params` drops the route out of `prerender-manifest.json` and
therefore out of every lock at once (Pitfall 8).

**Error handling: there is none, deliberately, and that is the pattern.** `dynamicParams = false`
means an unlisted segment 404s at the edge of the router and never reaches a lookup, which is also
the mitigation for the only user-controlled input in the build. Do not add a `try`/`catch` and do not
call `notFound()`.

The three band orders (§9.3, §9.4, §9.5) — `SectionBand`'s `paper` emits no modifier class, the Hero
sits on its own `paper-warm` ground outside the sequence, and `InterlinkBlock` is not a `SectionBand`
but paints as `paper`:

```
combo   Breadcrumbs · Hero · paper Prose · warm "What's included" · tint slider ·
        paper ProcessSteps · warm ReviewRail · interlink services · interlink nearby ·
        tint FAQ · navy CTABand
hub     Breadcrumbs · Hero · paper Prose · warm service cards · tint ProcessSteps ·
        warm ReviewRail · interlink nearby · tint FAQ · navy CTABand
index   Breadcrumbs · Hero(centered) · paper Prose + TrustBar · warm jump links + county groups ·
        tint ProcessSteps · warm ReviewRail · navy CTABand
```

Two colour rules these orders exist to satisfy: a `ReviewRail` inside a `tint` band is tint cards on
a tint ground, and neither `TownCard` nor `RatingBadge` may sit on `navy` or `ink` because both set
their ink colour directly rather than inheriting.

Breadcrumb trails (§7.3): index `Home › Locations`; hub `Home › Locations › {Town}`; combo
`Home › Locations › {Town} › {Service noun}`. The crumb label for `/locations` is **`Locations`**
while the header nav label for the same URL is **`Areas We Cover`** — two labels, one destination,
deliberately (§13-H).
