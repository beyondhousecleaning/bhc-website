```js
// The assembly order — 03-UI-SPEC §10.2, blocks 2 to 6. This IS the contract.
comboBlocks(town, serviceSlug) === [
  ...TOWN_PROSE[town.slug].opener,          // block 2 — town axis,      ~180 words
  ...variantA(serviceSlug, town.a),         // block 3 — service × a,    ~300 words
  ...variantB(serviceSlug, town.b),         // block 4 — service × b,    ~260 words
  ...countyNote(serviceSlug, town.county),  // block 5 — service × county, ~90 words
  ...TOWN_PROSE[town.slug].localityBlocks,  // block 6 — town axis,      ~130 words
]                                           //                    total ~960 + a 35-word lead

// The title chain — §5, measured. NOT a pattern; a two-candidate deterministic chain.
const full = `${titleNoun} in ${town.name} | ${BRAND}`;
comboTitle = full.length <= 60 ? full : `${titleNoun} in ${town.name}`;

// The description — §5, fixed length 102, subject is the DISPLAY noun (not the title noun),
// so the description carries the full term the title had to abbreviate.
// `Rated {rating} by {count} {source} reviews. {noun} in {Town} from DBS-checked, insured local
//  cleaners. Free quote in two minutes.`   → measured range 124-148 against a 155 cap.
```

`describe()` in `site.js` hard-codes `across ${AREA_SHORT}` and does **not** fit a combo page. The
combo form is a new function; do not reuse or "generalise" `describe()`, which the seven service
pages and eleven utility pages still depend on.

`RATING` lives once in `web/content/site.js` and the description interpolates it, so the description
cannot disagree with the badge on the same page.
