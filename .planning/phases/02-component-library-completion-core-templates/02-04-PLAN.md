Each component is a directory `design-system/src/components/<Name>/` holding EXACTLY the four
canonical files `<Name>.jsx`, `<Name>.html`, `<Name>.d.ts`, `<Name>.prompt.md`, plus:
  - a CSS block appended to `design-system/styles.css` in the existing `/* --- Name --- */` banner
    style, values exclusively `var(--bhc-*)`, NO literal hex;
  - a named export in `design-system/src/index.js`, path `./components/<Name>/<Name>.jsx`;
  - `<!-- @dsCard group="…" -->` on LINE 1 of the `.html` (exact regex, no leading whitespace),
    followed by `<link rel="stylesheet" href="../../../styles.css" />`;
  - `category: <same group>` frontmatter on the `.prompt.md` — delta 9 asserts they agree;
  - an entry in BOTH `componentSrcMap` and `docsMap` in `.design-sync/config.json`.

Group is one of `Navigation` / `Content` / `Trust` / `Actions`. Do not invent a fifth.

Hard rules inherited from D-04 / D-06 / D-07:
  - No `import React`. No bare specifiers. Sibling relative paths with the extension always written.
  - No client directive, no `useState`, no `useEffect`, no event-handler props, anywhere.
  - Never `&&` in JSX — use a ternary to `null`. `0 && …` renders `0`.
  - `className` merge idiom: `['bhc-<block>', <modifier or ''>, className].filter(Boolean).join(' ')`.
  - Variant maps with a fallback: `TONES[tone] || TONES.paper`, so an unknown value degrades to the
    default and never emits `bhc-section--undefined`.
  - Every file ends `export default <Name>;`.
  - Return type in the `.d.ts` is `JSX.Element`, or `JSX.Element | null` when the component can
    return null.
  - Pure string-manipulation logic goes in a plain `.js` sibling, never in the `.jsx` — the
    `claude-seo` PostToolUse hook rejects a `.jsx` write containing the case-insensitive substring
    `REPLACE`, which every `.replace(` contains.
  - Comments state measured evidence, not intent. Quote the ratio from UI-SPEC §4, not an adjective.

Classes already shipped and NOT to be re-declared: `bhc-container`, `bhc-container--narrow`,
`bhc-container--wide`, `bhc-section`, `bhc-section--warm`, `bhc-section--tint`, `bhc-section--navy`,
`bhc-visually-hidden`, `bhc-skip-link`. `.bhc-section__intro` was added by plan 02-01 and is the
shared intro/lead treatment — do not borrow `.bhc-hero__lead` again.

**CTABand** — group `Content`, root `<section class="bhc-section bhc-section--navy">`.

Props per §7.10: `heading` (required), `lead`, `actions`, `tone` (`'navy' | 'tint'`, default
`'navy'`). Compose the band the same way `SectionBand` does rather than duplicating its padding
logic. One `primary` and one `ghost` action, mapped through `Button` exactly as `Hero.jsx:59-72`
does. **One per page, always immediately above the footer** — state that in the header comment and
the `.prompt.md`.

Two hard rules to record as measured evidence, not adjectives:
- On navy, `Button variant="secondary"` is an outlined ink button and disappears. Use `ghost`.
- **Never place `RatingBadge` inside a `CTABand`.** `.bhc-rating__value` and `.bhc-rating__count`
  set `--bhc-ink` and `--bhc-ink-muted` directly rather than inheriting `currentColor`, so the badge
  is light-surface only and is illegible on navy. Put it in the `## Don't` list.

**The two scoped focus overrides.** Append them to `design-system/styles.css` AFTER every component
block, under a banner comment reading that this section must remain last in the file and that every
later plan appends its component block ABOVE it. Exactly these two rules and nothing else:

1. `.bhc-section--navy .bhc-btn--primary:focus-visible`, `.bhc-section--navy :focus-visible` and
   `.bhc-footer :focus-visible` take `outline-color: var(--bhc-paper)`. Reason, measured:
   `--bhc-action-hover` on `--bhc-navy` is 1.15:1 — effectively invisible — while `--bhc-paper` on
   navy is 5.97:1, on ink 15.81:1, and on an orange fill 3.05:1 (enough for a non-text indicator
   under 1.4.11). The first selector exists because ink-on-navy is 2.65:1, so a primary button
   inside the CTABand must take the white ring rather than the ink one, and it wins on specificity.
2. `.bhc-btn--primary:focus-visible` takes `outline-color: var(--bhc-ink)`. Reason: an orange ring
   abutting an orange fill reads as one blob, especially on hover when the fill IS
   `--bhc-action-hover`. Ink is 15.81:1 against the band and 5.17:1 against the fill. White would be
   1:1 on a white band, which is why it is ink and not paper.

`outline: none` is never acceptable anywhere. Nothing else may change the focus indicator.

Previews: ProcessSteps uses Shape C (the three real steps). CTABand uses Shape B, showing the navy
variant and the tint variant as labelled cells, plus a labelled negative cell demonstrating that
`secondary` disappears on navy so the failure is recognisable — copy `Button.html`'s negative-cell
idiom.

Register both components in `index.js` and both `.design-sync/config.json` maps.
