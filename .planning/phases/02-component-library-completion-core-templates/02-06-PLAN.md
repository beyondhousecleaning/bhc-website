<objective>
Create the app-side data layer the templates and the lock harness both depend on: a `@/*` path
alias and the site-copy modules that are not tied to a single route (`site.js`, `nav.js`,
`process.js`, `faqs.js`).

Purpose: framework-agnostic UI components must not carry site copy, and the copy must not live in
`.jsx` files — the `claude-seo` PostToolUse hook rejects a `.jsx` write containing the
case-insensitive substring `REPLACE`, which ordinary prose like "we'll replace" contains. A sibling
`web/content/` directory plus the alias is also stable at any route depth, which matters when Phase 3
authors `app/location/[region]/[town]/[service]/page.jsx`.

Output: `web/jsconfig.json` and four data modules. No route file changes in this plan.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| data module -> root layout -> every route | `nav.js` is consumed by `Header` and `Footer` inside the root layout, so a malformed entry has a 17-route (later ~410-route) blast radius |
| authored copy -> built HTML | FAQ answers and step bodies are the first real prose volume the postcode and street-line matchers meet |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-30 | Denial of Service | `nav.js` malformed entry | mitigate | Data authored to the exact `FooterColumn`/`NavItem` shapes, and `NAPFooter`'s shipped `.filter(Boolean)` / `(col.links \|\| [])` guards absorb a bad entry rather than throwing during server render (task 2) |
| T-02-31 | Information disclosure | address or postcode in copy | mitigate | Explicit prohibition in the module header, an acceptance check for postcode-shaped strings and long digit runs, and plan 02-02's `SC-2d` scanning built HTML on every page (task 2) |
| T-02-32 | Tampering | a nav href to a route that does not exist | mitigate | Acceptance criterion enumerates the 17 routes and fails on any other href; plan 02-02's delta 6 enforces it against the real manifest once the layout renders the nav (task 2) |
| T-02-33 | Information disclosure | a second phone number entering the app | mitigate | Digit-run check on all four content modules; the canonical number stays in `design-system/src/phone.js` and `web/app` keeps returning zero hits for it |
| T-02-34 | Tampering | npm/pip/cargo installs | mitigate | Not applicable — zero packages this phase; `jsconfig.json` is configuration, not a dependency |
</threat_model>
