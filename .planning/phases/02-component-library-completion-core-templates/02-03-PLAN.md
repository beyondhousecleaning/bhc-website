Failing at build time across 410 prerendered pages is strictly better than a dead phone line in
production.

**Delta 14 — inline SVG accessibility.** Add a test that reuses the existing `walk` idiom over
`design-system/src`, filtered to `.jsx` and `.html`, extracts every `<svg …>` opening tag, and
asserts for each:
- it carries NO `alt` attribute. `alt` is not valid on `<svg>`, it is silently dropped, and Lock 7
  greps `<img>` tags only — so this class of defect is currently invisible.
- it carries EITHER `aria-hidden="true"` OR both `role="img"` and a non-empty `aria-label`.

Do not scan `.d.ts` or `.prompt.md`; they are types and prose, not rendered output. The failure
message must name the file and print the offending opening tag.

Add the paired regression guard: a `mustMatch` array containing a decorative form
(`<svg aria-hidden="true" focusable="false">`), a meaningful form
(`<svg role="img" aria-label="Before-and-after comparison">`), and a JSX-attribute-order variant;
and a `mustNotMatch` array containing an `<svg>` with `alt="x"`, an `<svg>` with neither mechanism,
and an `<svg role="img">` with an empty `aria-label`. Without the guard, an extractor that quietly
stopped matching `<svg` would read green across sixteen new components.

Note in a comment that all existing SVGs already comply, so this lock passes on landing — which is
the point: it is a guard for the fourteen SVGs waves 2 through 5 will author, not a repair.
