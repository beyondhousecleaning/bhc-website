<!-- Identical to plans 02-04 and 02-05. Repeated so this plan is self-contained. -->

Each component is a directory `design-system/src/components/<Name>/` holding EXACTLY the four
canonical files, plus a CSS block in `design-system/styles.css` **appended ABOVE the focus-override
banner, which must remain the last section of the file**, a named export in
`design-system/src/index.js`, `<!-- @dsCard group="Trust" -->` on LINE 1 of the `.html` followed by
`<link rel="stylesheet" href="../../../styles.css" />`, `category: Trust` frontmatter on the
`.prompt.md`, and an entry in BOTH `componentSrcMap` and `docsMap` in `.design-sync/config.json`.

Hard rules: no `import React`; sibling relative paths with the extension always written; no client
directive, `useState`, `useEffect` or event-handler props anywhere; never `&&` in JSX (ternary to
`null`); the `.filter(Boolean).join(' ')` className merge; variant maps with a fallback;
`export default <Name>;` at the end of every file; `JSX.Element | null` in the `.d.ts` when the
component can return null; pure string manipulation in a plain `.js` sibling, never in a `.jsx`;
values exclusively `var(--bhc-*)` with no literal hex; comments state measured evidence.

**Never write the client directive literally anywhere under `design-system/src` or `web/content` —
including prose, header comments and `## Don't` lists.** Plan 02-02 extends the client-boundary
source scan to those two roots, and it is a plain substring grep, so an explanatory sentence naming
the directive turns `check:html` red for the whole phase. `web/app/page.jsx:11-15` already follows
this convention for exactly this reason: refer to it as "the client directive" and never spell it.
Zero occurrences exist today; this collision has already bitten this repo three times.

**Inline SVG rule (delta 14 asserts it):** every `<svg>` carries either `aria-hidden="true"` (when
adjacent text already names it) or `role="img"` plus a non-empty `aria-label` (when it is the only
content of its figure). **Never `alt` on an `<svg>`** — it is not a valid attribute, it is silently
dropped, and Lock 7 greps `<img>` tags only.

**ReviewCard** — root `<article class="bhc-review">`.

Props per §7.13: a `Review` shape of `{ quote, author, town?, rating, date, source? }`. Structure:
five stars, then a `<blockquote>` at `--bhc-text-lg` / line-height 1.35, then the attribution as
`<p class="bhc-review__by"><cite>{author}</cite> · {town} · {date}</p>`.

**Import `Star` from `'../RatingBadge/RatingBadge.jsx'`** — plan 02-01 exported it precisely so the
glyph path data exists in one file. Wrap the five glyphs in a `role="img"` element carrying an
`aria-label` built once into a `const`, with each individual `Star` `aria-hidden`.

Three prohibitions, each with its reason, in the header comment and `## Don't`:
- **The attribution is deliberately NOT a nested `<footer>`.** That is legal HTML inside `<article>`,
  but it would break the "exactly one `<footer>` per page" assertion in `check-html-locks.mjs`.
- **No `-webkit-line-clamp`.** With no client JavaScript there is no "read more", so a CSS clamp
  hides text from sighted users that screen readers still receive, and the loss widens at 200% zoom
  (WCAG 1.4.4). **The quote is capped at 320 characters at the DATA LAYER**, truncated at a word
  boundary with an ellipsis at ingest, so what ships is exactly what displays. Phase 4's review pull
  must honour this cap — it is a property of the data contract, not of the CSS. Say so in the `.d.ts`
  JSDoc on `quote`.
- **Emits no review schema.** Self-serving and widget-sourced review markup are both ineligible, and
  `AggregateRating` is entity-graph only, emitted once per page by `RatingBadge`.

Ground `--bhc-paper-tint`, radius `--bhc-radius-lg`, padding `--bhc-space-6`. **No links inside the
card** — that is what makes the rail's `tabindex="0"` correct, so record the coupling in both
`.prompt.md` files.
