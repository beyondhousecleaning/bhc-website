<objective>
Make the two sanctioned changes to the `@bhc/design-system` package that Phase 1 requires, and
nothing else.

1. Expose `fonts/` through the package `exports` map. Without this,
   `import '@bhc/design-system/fonts/fonts.css'` — which the app's root layout needs — fails hard
   with `ERR_PACKAGE_PATH_NOT_EXPORTED` (Turbopack surfaces it as `Module not found`). This is
   measured, not speculative (01-RESEARCH.md Pitfall 1).
2. Close the JSON-LD script-injection sink. All three JSON-LD-emitting components interpolate
   values into `dangerouslySetInnerHTML` via bare `JSON.stringify`, which does not escape a
   `</script>` sequence. Low exploitability today (every value is hardcoded); materially
   exploitable from Phase 3, when ~56 town names arrive from a data file and feed these same
   components at ~336-page scale.

Purpose: unblock Plan 02's root layout, and fix the phase's one real security defect at the point
where it costs two lines per component instead of a Phase-3 retrofit across 336 pages.

Output: an amended `design-system/package.json`, a new `design-system/src/jsonLd.js`, three
one-identifier component swaps, and two new lock tests that turn the escape from a hope into a lock.

This plan deliberately runs first and alone in Wave 1: it needs no `node_modules`, no build, and no
app, so it can be fully verified against a clean checkout before any tooling exists.
</objective>
