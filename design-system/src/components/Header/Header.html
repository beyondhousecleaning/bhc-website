The mechanism, and why the disclosure looks empty

The <details class="bhc-nav__disclosure"> above holds a <summary> and nothing else. It is a state carrier. The one <ul> is its sibling, and a sibling combinator in styles.css shows the list while the disclosure is open. A user agent only hides a disclosure's own children, so a sibling is untouched by it.

Below 1024px the toggle is the navigation. At 1024px and above the toggle is removed and the list is unconditionally display:flex, so the open state stops mattering. One <nav aria-label="Primary">, one <ul>, every link in the DOM exactly once, and no JavaScript anywhere.

What breaks if the list is moved inside the disclosure

Desktop navigation disappears. A closed disclosure's non-summary children are hidden by the user agent, not by a display rule a stylesheet can override, so hiding the toggle at 1024px would leave the list permanently invisible. The empty element is deliberate. The Services submenu below it is the other case — an ordinary disclosure that does contain its own list, opened by the user agent, no combinator involved.
