An entry point, not a form

There is no <form> and no <input> in this panel, and there is not going to be one. Booking-flow UX belongs to a separate product and is out of scope for this site; on top of that, a real form needs validation state, validation state needs a client boundary, and a first-party client boundary turns SC-4g red — the lock that asserts every client module in the build resolves inside Next itself. One text input would cost the phase its central architectural claim.

The number is not typed into this component. It arrives from src/phone.js; the label comes from formatPhone() and the href from toDial(), both derived from that same one value. The live site displays one number and dials another on all 115 pages, which is only possible when the two are separate inputs.
